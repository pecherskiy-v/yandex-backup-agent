# Яндекс.Диск как место хранения резервных копий

Кастомная интеграция: после установки Диск появляется в
**Настройки → Система → Резервные копии** наравне с локальным хранилищем —
отдельной кнопки и ручного копирования не нужно.

## Зачем, если есть WebDAV

У Диска есть WebDAV, и HA умеет с ним работать «из коробки», но большие
файлы через него не уезжают: сервер принимает тело PUT, не отвечает, и
соединение висит, пока не умрёт по таймауту. В журнале это выглядит как
`Backup operation failed: No connection with https://webdav.yandex.ru`, хотя
связь есть и мелкие запросы проходят.

REST API устроен иначе: сначала берётся одноразовая ссылка на загрузку,
и файл льётся на storage-узел — тем же путём, что у родного клиента Диска.
Размер уходит заголовком `Content-Length`, так что тело не режется на
chunked, на котором Диск и спотыкается.

## 1. Получить токен

Токен выпускается один раз, руками, в браузере — ни HA, ни этот код паролей
от Яндекса не видят.

1. Открыть <https://oauth.yandex.ru/client/new/>.
2. Платформа — «Веб-сервисы», Redirect URI — `https://oauth.yandex.ru/verification_code`.
3. Доступы (раздел «Яндекс.Диск REST API»):
   `cloud_api:disk.read`, `cloud_api:disk.write`, `cloud_api:disk.info`.
4. Создать приложение, скопировать **ClientID**.
5. Открыть в браузере, подставив свой ClientID:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`
6. Разрешить доступ. Токен — в адресной строке после `access_token=`.

Токен даёт полный доступ к Диску: хранить как пароль, в переписку не класть.

## 2. Поставить компонент

### Через HACS

HACS → три точки → «Custom repositories» → вставить `https://github.com/pecherskiy-v/yandex-backup-agent`,
категория «Integration» → установить → перезапустить HA.

### Руками

Скопировать каталог в конфиг HA и перезапустить:

```
<config>/custom_components/yandex_disk_backup/
```

## 3. Подключить

**Настройки → Устройства и службы → Добавить интеграцию → «Яндекс.Диск
(копии)»**. Вставить токен, при желании поменять папку (по умолчанию
`Home Assistant/backups`) — она создастся сама, вместе с родительскими.

После этого в разделе резервных копий появится место хранения
`Яндекс.Диск · <логин>`: его можно отметить в расписании, и копии поедут
туда автоматически.

## Как оно лежит на Диске

Рядом с каждым архивом лежит файл метаданных с тем же именем — раскладка
та же, что у штатного агента WebDAV:

```
Home Assistant/backups/
  Automatic_backup_2026.9.2.tar
  Automatic_backup_2026.9.2.metadata.json
```

Список копий строится по метаданным: в них есть всё, что показывает
интерфейс, и качать ради этого гигабайтный архив не нужно. Метаданные
пишутся **после** архива — значит, копия без метаданных не доехала, и в
списке она не появится. Огрызок такой копии остаётся на Диске: удалять его
нужно руками, зато HA никогда не предложит восстановиться из обрезанного
архива.

Удаление идёт мимо корзины: корзина Диска считается в тот же объём, и
«удалённые» копии продолжали бы занимать место.

## Грабли

- **Токен протухает.** Тогда запись уходит в ошибку и HA сам просит новый —
  папка и настройки при этом сохраняются.
- **Свободное место.** Полный бэкап HA — сотни мегабайт, а бесплатный Диск
  это 10 ГБ. Ретеншен (сколько копий хранить) задаётся в самом HA, в
  настройках расписания, отдельно для каждого места хранения.
- **Скорость.** Диск не обещает быстрой отдачи; первая копия на 300 МБ может
  ехать несколько минут. Таймаут на загрузку — 12 часов, обрыв связи
  агент честно покажет ошибкой, а не молчанием.
- **Копия без базы.** Если гонять копии часто, стоит выключить в расписании
  включение базы рекордера — она и есть основной вес архива.
